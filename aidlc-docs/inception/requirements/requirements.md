# Requirements: Word Book (단어 암기 애플리케이션)

## Intent Analysis Summary

- **User Request**: 로컬에서 혼자 쓰는 단어 암기 웹 앱 개발 (단어+뜻 입력, 목록 관리, 외움 체크, 로컬 영구 저장)
- **Request Type**: New Project (Greenfield)
- **Scope Estimate**: Multiple Components (단일 백엔드 유닛 + 단일 프론트엔드 유닛)
- **Complexity Estimate**: Simple (CRUD 기반 단일 사용자 로컬 앱, 명확한 범위와 제외 목록 명시됨)

## 1. 기능 요구사항 (Functional Requirements)

### FR-1. 단어 추가
- 사용자는 단어(word)와 뜻(definition)을 입력하여 새 항목을 추가할 수 있다.
- 단어와 뜻은 필수 입력이며, 빈 값(공백만 있는 값 포함)은 허용하지 않는다.
- 단어와 뜻의 길이 제한은 없다 (빈 값만 방지).
- **중복 단어 처리**: 이미 존재하는 단어를 다시 추가하려는 경우, 기본적으로 중복을 방지하고 사용자에게 "중복 단어입니다. 정말 다시 추가할까요?"와 같은 확인 메시지를 표시한다. 사용자가 확인하면 강제로 추가할 수 있다 (동일 단어의 중복 등록 허용).

### FR-2. 단어 목록 보기
- 저장된 모든 단어 항목(단어, 뜻, 외움 상태)을 목록 형태로 표시한다.
- 기본 정렬 순서는 **최근 추가한 것이 먼저** 오도록 한다 (역시간순).
- 정렬 옵션 변경 기능(가나다순 등)은 범위에서 제외한다.

### FR-3. 단어 수정
- 사용자는 기존 항목의 단어 및/또는 뜻을 수정할 수 있다.
- 수정 시에도 빈 값 검증이 동일하게 적용된다.

### FR-4. 단어 삭제
- 사용자는 기존 항목을 삭제할 수 있다.
- 삭제 전 확인 다이얼로그("정말 삭제하시겠습니까?")를 표시하고, 사용자가 확인해야 실제로 삭제가 진행된다.

### FR-5. 외움 체크
- 각 항목은 "외움" 또는 "안 외움" 상태를 가진다.
- 사용자는 항목별로 이 상태를 토글할 수 있다.

### FR-6. 로컬 영구 저장
- 모든 데이터(단어, 뜻, 외움 상태)는 SQLite에 저장되어 브라우저/서버를 재시작해도 유지된다.
- 데이터베이스 파일은 프로젝트 내 `data/` 디렉토리에 저장한다 (예: `data/wordbook.db`).

## 2. 제외 범위 (Out of Scope)

다음 기능은 명시적으로 이번 프로젝트 범위에서 제외한다:
- 상태 필터(전체/외운 것/안 외운 것), 진행률 표시(개수·%), 단어 검색
- 단어 정렬 옵션(가나다순/최근순 전환), 백업 내보내기/가져오기
- 로그인/계정/멀티유저, 서버·클라우드 동기화
- 알림/리마인더, 간격반복(SRS) 학습 알고리즘
- 모바일 네이티브 앱, 다국어 UI(i18n)

## 3. 비기능 요구사항 (Non-Functional Requirements)

### NFR-1. 대상 사용자 및 환경
- 단일 사용자(본인 1명), 단일 브라우저/PC 환경에서 로컬로 실행.
- 규제/컴플라이언스 대상 아님.

### NFR-2. 대상 브라우저
- 최신 Chrome, Edge, Safari에서 정상 동작해야 한다.

### NFR-3. 실행 환경 범위
- 로컬 환경에서 빌드, 실행, 테스트가 완료되어야 한다.
- 실배포, 클라우드 인프라, CI/CD 파이프라인 구축은 범위 밖이다.

### NFR-4. 확장 규칙 적용 여부
- **Security Baseline**: 비활성화 (개인용 로컬 앱, 프로덕션 보안 강제 규칙 불필요)
- **Resiliency Baseline**: 비활성화 (프로토타입 수준, 고가용성/복원력 설계 불필요)
- **Property-Based Testing**: 비활성화 (단순 CRUD 앱, PBT 불필요 — 일반 단위/통합 테스트로 충분)

## 4. 기술 결정 (Technical Decisions)

| 영역 | 결정 |
|---|---|
| 프론트엔드 | React SPA (Vite 빌드 도구 사용) |
| 백엔드 | Node.js + Express |
| 데이터 저장 | SQLite (런타임 내장 드라이버: `node:sqlite` 또는 `bun:sqlite`, 네이티브 컴파일 불필요) |
| DB 파일 위치 | `data/wordbook.db` (프로젝트 루트 기준) |
| 백엔드 포트 | 4000 |
| 프론트엔드 개발 서버 포트 | 5173 (Vite 기본값) |
| 산출물 구조 | 유닛 2개: `backend/` (Express + SQLite API), `frontend/` (React SPA) |

## 5. 데이터 모델

각 단어 항목:
```
{
  id: 고유 식별자,
  word: string (필수, 공백 불가),
  definition: string (필수, 공백 불가),
  memorized: boolean (외움 상태, 기본값 false)
}
```

## 6. 사용자 시나리오

1. 사용자가 단어와 뜻을 입력하고 "추가" 버튼을 누르면 목록 최상단에 새 항목이 나타난다.
2. 이미 존재하는 단어를 입력하고 추가를 시도하면 확인 메시지가 뜨고, 확인 시 중복 항목이 추가된다.
3. 사용자가 목록에서 특정 항목의 체크박스/토글을 클릭하면 외움 상태가 즉시 전환되고 저장된다.
4. 사용자가 항목을 수정하면 입력 폼에 기존 값이 채워지고, 저장 시 값이 갱신된다.
5. 사용자가 삭제 버튼을 클릭하면 확인 다이얼로그가 뜨고, 확인 시 항목이 목록과 DB에서 제거된다.
6. 사용자가 브라우저를 닫고 다시 열어도(백엔드 서버가 실행 중이라면) 이전에 입력한 모든 데이터가 그대로 표시된다.

## 7. 산출물 구조 (Units)

- **Unit 1 - Backend**: Express REST API + SQLite 데이터 액세스 (CRUD 엔드포인트: 단어 목록 조회, 추가, 수정, 삭제, 외움 상태 토글)
- **Unit 2 - Frontend**: React SPA (단어 추가 폼, 목록 뷰, 수정/삭제 UI, 외움 체크 토글), 백엔드 API 호출

## 요약

단순하고 명확한 범위를 가진 로컬 단일 사용자 단어 암기 CRUD 웹 앱입니다. React(Vite) + Express + SQLite 스택으로 백엔드/프론트엔드 2개 유닛으로 구성되며, 보안/복원력/PBT 확장 규칙은 모두 비활성화됩니다. 중복 단어는 확인 후 강제 추가를 허용하고, 삭제는 확인 다이얼로그를 거칩니다.
